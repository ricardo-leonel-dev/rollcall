## Deviations from the spec — acceptable, documented

- **Comma-grouped CSS selectors between `.courses-folio` and `.citation-reasons-folio`** — the spec asked for "keep the per-list folio self-contained". The implementer kept each wrapper class distinct (so Cursos and Motivos can move independently of each other and of `.users-folio`), but shared the identical geometry rules via comma-grouped selectors. Justified by the 5 kB component-CSS error budget; if they'd duplicated the rules, the file would have crossed the error threshold. Each wrapper class is still its own scope — `grep '.courses-folio\b'` finds only Cursos, `grep '.citation-reasons-folio\b'` finds only Motivos.
- **Folio text uses `Registros:` (not `Registrados:`)** — the description's `'Registrados: NNN'` was a typo; the implementer matched feature 30's already-shipped `Registros:` prefix. Consistent with `progress/impl_30.md` and the existing `.users-folio` shipping pattern.
- **Permisos smoke doesn't auto-select a role** — `selRole` starts as `null`, the permissions matrix is gated on `@if (permissions().length)`, so the Permisos smoke's table area is empty. Pre-existing UI behavior, not introduced by feature 34. The eyebrow + filete + folio-absent assertions still validate the spec's intent (eyebrow renders, double filete renders, no folio is added). Auto-selecting a role in the smoke would tightly couple the smoke to fixture internals for no real coverage gain.

## Notes for the leader (not blocking)

- The smoke's eyebrow `full` field concatenates the mat-icon's ligature text (`admin_panel_settings`) with the rest of the eyebrow. This is a DOM extraction artifact (the icon's text node lives inside the eyebrow span), not a visual issue — the icon renders as a glyph and the rest renders with chapter-eyebrow spacing. Same artifact existed in feature 33 and was benign there.
- The build's component-CSS warning grew from 3.04 kB to 4.67 kB (still under the 5 kB error budget). If the admin component grows further, the cleanest long-term fix would be to extract shared folio rules into a global `.class-card-folio` in `styles.css` and have each tab's wrapper class just be a namespacing hook — but this is not required by feature 34's acceptance.
